# Decisions

Append-only. These are not preferences: they are decisions made for specific
reasons, and changing them requires going back to those reasons. New rows at
the bottom; a superseded decision gets a new row naming the old one, never an
edit.

| 3 | 2026-11-25 | Amit ("do all") + Claude | **Snapshots are protected by passphrase encryption of the whole zip, with `cryptography` as a required dependency.** Why: `settings.json` can hold keys and 0.2.0 shipped it in plain zips; encrypting the whole object covers every backend and every file. scrypt (N=2^15, r=8, p=1) and AES-256-GCM, header as associated data, magic `CCFGENC2`. A plain snapshot is refused when local encryption is on unless `--allow-plain` is passed, because a reviewer restored a planted plain zip with no passphrase. Rejected: redacting known secret fields on push (misses unknown fields and breaks restore), and only warning (protects nothing); making `cryptography` an extra (encryption would be off on a plain install). Proof: all 63 truncations and 63 bit flips of an envelope were rejected in review. Files: `claude_cfg/encryption.py`, `passphrase.py`, `passphrase_verifier.py`, `snapshot_store.py`. |
| 4 | 2026-11-25 | Claude | **`pull` stays an overlay by default; removing files is opt-in through `--exact`, behind a confirmation, and only inside roots that both the snapshot and this machine's config track.** Why: deleting by default would surprise 0.2 users, and a snapshot's own `tracked` list is attacker-influenced input: in review a manifest listing `history.jsonl` and `file-history` got them planned for deletion. Excluded paths are never deleted. Rejected: exact as the default. Files: `claude_cfg/restore_plan.py`, `pull_manager.py`, `exclusion_filter.py`. |
| 5 | 2026-11-25 | Claude | **The objects under `snapshots/` are the source of truth and `index.json` is a cache; a pusher that sees any other object with its id yields and retries under a new id.** Why: 0.2.0 read, appended and rewrote `index.json` with no lock, so two machines could drop a snapshot or reuse an id. A first version of the rule (lower key wins) had a window where a late rival concluded it had won; yield-always closed it. Proof: 150 threaded rounds of three pushers, no duplicate, lost or orphaned snapshot. A lagging sync folder can still show two objects with one id; that is reported and `pull --key` selects one. Files: `claude_cfg/snapshot_store.py`, `snapshot_index.py`, `snapshot_keys.py`. |
| 6 | 2026-11-25 | Claude | **MCP servers are read from `.claude.json` and written only through `claude mcp add-json <name> - --scope user`, with the definition on stdin. The tool never writes `.claude.json`.** Why: that file mixes MCP config with account and per-project state, Claude Code rewrites it while running, and hand-editing it is not documented; definitions hold tokens, and command-line arguments are visible to other local processes. Consequence: restore needs the `claude` CLI at 2.1.327 or later and a terminal outside a Claude Code session, and is skipped with a report otherwise. Rejected: writing the JSON key directly (corruption and clobber risk); not syncing MCP at all. Opt-in, default off. Files: `claude_cfg/mcp_server_sync.py`, `mcp_cli_preflight.py`, `mcp_server_capture.py`. |
| 7 | 2026-11-25 | Claude | **Session notices are printed as a `systemMessage` JSON line, never as plain hook output.** Why: the docs say a SessionStart hook's plain stdout goes into Claude's context. Files: `claude_cfg/session_hook_manager.py`, `session_start_notice.py`. |
| 8 | 2026-11-25 | Claude | **On a case-insensitive disk, snapshot names match files by folded name; on a case-sensitive disk only the exact name matches. The exclusion filter folds on every platform.** Why: on macOS an exact pull wrote `skills/foo/SKILL.md` into `skills/Foo/` and then deleted it as a local extra, and `.Credentials.json` overwrote the credentials file; folding everywhere then broke Linux, where `README.md` and `Readme.md` are two files. The filter over-excludes on purpose, since excluding too much is the safe direction. The disk is probed with a temp file. Files: `claude_cfg/path_matching.py`, `path_identity.py`, `exclusion_filter.py`. |
| 9 | 2026-11-25 | Amit | **The plugin is named `config-history`.** Why: plugin names starting with `claude-`, `anthropic-`, `anthropics-` or `cc-plugin-` are reserved, so `claude-cfg` cannot be used; the name states what most users want it for. | 10 | 2026-11-25 | Amit (behavior) + Claude (defaults) | **When config changed, the plugin saves a local version automatically at session start and end and shows one line. | 15 | 2026-11-25 | Amit (scope: "Essentials + extras") + Claude (rules) | **The plugin has three skills and one command to remember. `/config-history:restore` is a guided flow (list, pick by number or in words, preview, all or some files, confirm, restore). `/config-history:undo` reverts it. This narrows row 14: its rule (pre-approve read-only commands only) stands, its claim that the permission prompt is the confirmation is superseded.** Why: the owner's bar was "it should be super easy or it won't work", and six skills made a new user choose a command before knowing what any did. ## Open questions

Intentionally deferred decisions. Each states the question and the trigger for
revisiting it. When resolved, it becomes a decision row and is struck from
this list with a pointer to that row.

1. **Submit the plugin to Anthropic's directory?** Deferred because the
   submission checklist (`claude.com/docs/plugins/pre-submission-checklist`)
   has not been read and the plugin has not been published or tried
   interactively. Revisit after the first release from the own marketplace;
   read the checklist first and report whether the plugin fits it. The icon
   decision matters here, since the first submitted icon is permanent
   (`docs/tickets/plugin-has-no-icon.md`).
2. **Should the PyPI package keep the name `claude-cfg`?** Only the plugin
   name is constrained today (row 9). The repository half of this question is
   settled: it is renamed to `config-history` (row 16). Revisit the package
   name if a directory submission or a trademark concern makes the difference
   between the two names a problem.
3. **Should auto-save be offered for a configured sync backend by default?**
   Row 10 leaves it off. Revisit when a user with a remote backend asks for it,
   or when there is evidence that the "changes not saved" notice is ignored.
4. **Should `diff` show what changed inside a file?** Deferred on 2026-11-25:
   `settings.json` and MCP definitions can hold keys, and inside the plugin a
   line diff would put them in Claude's context and the transcript, through a
   command the `history` skill pre-approves (row 15). Revisit when a user asks
   what changed inside a file, or before a directory submission. The options
   are in `docs/tickets/no-line-by-line-view-of-what-changed-inside-a-file.md`.
